## 一、3 分钟口播（连贯版 · 建议背）

**【0:00–0:20 开场】**  
您好，我带来练习项目 **「创灵」**——抖音创作者 AI 运营工作台，对应岗位 **创作者全链路**：选题、创作、发布、合规、成长，以及 **AI 作品诊断**。  
在线 Demo：https://aurora132731.github.io/douyin-creator-ai/ ，PRD 在 GitHub 仓库。

**【0:20–1:00 痛点 + 方案】**  
创作者四类痛：选题难、写得慢、怕违规、**有数据不知道改哪里**。  
抖音创作者中心已有 **作品数据详情**（四段漏斗），但数据和行动之间缺 AI。  
「创灵」把平台策略产品化：**阶段 × 垂类** 差异化；诊断交互借鉴 **小红书笔记诊断**——同类对标、现状/原因/建议，指标口径以 **抖音** 为准。

**【1:00–2:30 演示】**  
我走主流程：画像 → 选题 → 脚本 → 合规 → **AI 作品诊断** → 指标页。（具体操作见第二节。）

**【2:30–3:00 指标 + 收尾】**  
**L1** 按抖音四段漏斗：流量转化、开头吸引力、互动、内容深度。  
**L2** 对齐 JD：留存、效率、**P3 内容质量分**（5秒完播 35% + 全片完播 30% + 互动 20% + 点击率 15%，权重写在 PRD 里）、**P5 AI 诊断有效率**。  
当前 MVP：GitHub Pages + Mock，先验证机制；V1.1 大模型，V1.2 抖音开放平台。个人练习项目，非官方。谢谢。

## 二、演示操作脚本（边点边说 · 约 3 分钟）

| 步骤 | 点哪里 | 你说什么 |
|:----:|--------|----------|
| 1 | 总览 → **「开始演示」** | 工作台覆盖 JD 五段链路 + AI 诊断。 |
| 2 | 顶部改 **阶段 / 垂类** | 推荐会随画像变，阶段乘垂类机制。 |
| 3 | **AI 选题** → **采纳一条** | 解决选题难，对应漏斗上游。 |
| 4 | **AI 创作** → **生成脚本** | 钩子对应抖音 **§2 五秒完播**。 |
| 5 | **发布助手** | 清单 + 标题标签，优化 **§1 点击率**。 |
| 6 | **合规预检** → **「加载违规样例」** | JD 内容安全；**必点，效果最好**。 |
| 7 | **AI 作品诊断** → 选 **一篇已发布作品** → **「开始 AI 诊断」** | 先雷达看基础数据，再生成解读（按钮约 1–2 分钟态）。 |
| 8 | 生成完成后点 **「开头吸引力」** 卡片 | 浮窗：较好/待提升、同类中位数、**现状→原因→建议**。 |

| 10 | **产品方案** | PRD V2 摘要。 |

- 第 6 步务必点「违规样例」

## 三、指标（20 秒 · 指标页专用）

| 层级 | 答什么 | 举例 |
|------|--------|------|
| **L1** | 内容有没有变好 | 抖音作品详情 **四段漏斗**（非零散 KPI） |
| **L2** | 工具要不要迭代 | P1 留存、P2 效率、P3 质量分、P4 涨粉、**P5 诊断有效率**、P6 满意度 |

**P3 一句话（必背）：**  
5秒完播 **35%** + 全片完播 **30%** + 互动 **20%** + 封面点击率 **15%**；先归一化再加权，权重越高越贴近推荐冷启动与完播。

**AI 诊断一句话：**  
指标用抖音，形态学小红书——对标同类中位数，告诉用户**改哪里、为什么、怎么改**。

## 四、高频追问

| 问题 | 答法 |
|------|------|
| 为什么不用真 AI？ | MVP 验证链路与指标；V1.1 接豆包/通义。 |
| 数据真的吗？ | 数值 Mock；**结构**同抖音后台四段漏斗；诊断交互学小红书。 |
| 和创作者中心区别？ | 中心给数；创灵加 **AI 建议层** + 分维度诊断。 |
| 怎么证明 AI 有效？ | **P5**：采纳某维度建议后，该维度优于同类中位数；A/B 看 5 秒完播。 |
| P3 权重怎么定的？ | 开头 35%（冷启动）、完播 30%（流量池）、互动 20%、CTR 15%（入口且防标题党）。 |
| 合规能上线吗？ | 辅助预检，非法务终审。 |
| 为什么 Mock？ | 一天可演示；机制验证后再接 API。 |
