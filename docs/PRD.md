## 1. 背景与目标

### 1.1 业务背景

抖音创作者在内容全链路中普遍面临四类痛点：

| 痛点 | 表现 | 对应链路 |
|------|------|----------|
| 选题难 | 不知道拍什么、跟热点慢 | 选题 |
| 创作慢 | 脚本结构弱、前 3 秒留不住人 | 创作 |
| 违规风险 | 绝对化用语、行业红线踩坑 | 审核 |
| 复盘无方向 | 有播放无涨粉、不知道改哪里 | 成长 |

抖音创作者中心已提供播放量、完播率、涨粉量、流量来源、分体裁分析等数据能力，但**数据与行动之间缺少 AI 桥梁**。本产品旨在将平台策略与 AI 能力产品化，贯穿 JD 所述全链路：

**选题 → 创作 → 发布 → 审核 → 成长**

### 1.2 产品目标

1. **用户价值**：降低创作者从选题到发布准备的决策与执行成本。
2. **业务价值**：验证「阶段 × 垂类」个性化 AI 机制是否提升平台原生内容指标。
3. **面试/演示价值**：体现 AI 产品运营能力——需求分析、方案设计、指标定义、数据驱动迭代、合规意识。

### 1.3 与岗位的匹配

| JD 要求 | 产品体现 |
|---------|----------|
| 创作者全链路 AI 产品规划 | 五段生命周期工作台 |
| 阶段 × 垂类个性化机制 | 画像驱动选题/脚本/复盘差异化 |
| 数据驱动迭代 | L1 平台指标 + L2 产品指标 + A/B 看板 |
| AI 建议准确度与满意度 | P5 准确率、P6 满意度、采纳反馈 |
| 内容安全与合规 | 发布前合规预检 |
| 需求分析、PRD、原型 | 本文档 + 可交互 WebApp |

## 2. 用户画像与分层策略

### 2.1 目标用户

抖音垂类短视频创作者（个人为主），垂类包括：美食、美妆、知识、剧情、旅行、健身。

### 2.2 创作者分层

| 阶段 | 定义 | 运营重点 | AI 策略差异 |
|------|------|----------|-------------|
| **新手** | 粉丝 &lt; 1 万 | 选题命中率、5 秒完播、发布频次 | 低竞争选题 + 短脚本（25–35 秒） |
| **成长期** | 粉丝 1–50 万 | 人设差异化、系列化、互动转化 | 悬念结构 + 系列预告（45–90 秒） |
| **头部** | 粉丝 50 万+ | 商业转化、IP 延展、合规 | 品牌开场 + 商业植入自然过渡 + 严格合规 |

### 2.3 用户故事

**主流程：**

```
进入工作台 → 设置画像（昵称/阶段/垂类）
  → 【选题】浏览 AI 推荐，采纳 1 条
  → 【创作】生成脚本大纲，复制使用
  → 【发布】完成检查清单，复制标题/标签
  → 【合规】粘贴文案预检，修改至通过
  → 【成长】查看诊断与下期建议 → 回到选题（闭环）
```

**辅流程（面试官/运营）：** 总览 → 指标看板（L1+L2）→ PRD 页 → 理解产品思维。

## 4. 功能需求详述

### F1 AI 智能选题

**输入：** 创作者阶段、内容垂类  
**输出：** 选题卡片列表（标题、热度、竞争度、匹配分、推荐理由、话题标签、建议体裁/时长）

**规则：**
- 选题库按垂类配置（`TREND_TOPICS`）
- 新手阶段热度/匹配分加权上浮（`stageMultiplier`）
- 竞争度由热度推导：高热度 → 高竞争

**成功标准：** 用户可采纳选题并流转至创作页。

---

### F2 AI 脚本助手

**输入：** 已选选题 + 创作者画像  
**输出：** `ScriptOutline`（hook、structure[]、cta、duration、tips[]）

**规则：**
- 钩子模板按垂类差异化（美食/美妆/知识等）
- 分镜结构按阶段差异化（新手 4 段短结构 vs 头部深度结构）
- 未选题时展示引导，禁止空生成

**关联 L1 指标：** 5 秒完播率、2 秒跳出率、完播率（脚本质量代理）

---

### F3 发布助手

**输入：** 选题、画像  
**输出：** ≥5 项检查清单、建议发布时段、标题与标签草稿（可复制）

**规则：**
- 清单未全部勾选时提示警告
- 发布时段按垂类 mock（对标快手「粉丝活跃时段」思路）

**关联 L1 指标：** 投稿数、发布后 1h 播放量

---

### F4 合规预检

**输入：** 用户粘贴的标题/口播/描述文案  
**输出：** 合规分、风险项（高/中/低）、修改建议、是否通过

**规则：**
- 敏感词子串匹配 + 绝对化词加权扣分
- 存在「高」风险项且分数 &lt; 70 不通过
- 固定建议：免责声明、#广告 标注、避免标题党

**关联指标：** 违规驳回率下降（A/B 护栏）

---

### F5 成长复盘

**输入：** 创作者画像 + mock 账号数据  
**输出：** ≥3 条可执行建议（含阶段差异化 tip）

**关联 L1 指标：** 涨粉量/粉丝净增量、互动指数

---

### F6 指标看板

展示双层指标体系、趋势图、A/B 实验、分功能采纳率。详见第 6 章。

---

### F7 PRD 展示页

应用内只读摘要 + 链接 `docs/PRD.md` 完整版。

## 6. 核心指标体系

> **设计原则：** L1 回答「内容是否变好」；L2 回答「AI 工具是否值得迭代」。二者不可混用。

### 6.1 指标逻辑链

```
AI 建议（选题/脚本/合规）
  → 创作者采纳 & 发布
    → L1 平台指标变化（完播、涨粉、互动…）
      → 反哺 L2（AI 准确率、满意度）
        → 功能迭代（A/B、词库、模板）
```

### 6.2 L1：平台原生指标（内容结果层）

#### 6.2.1 抖音创作者中心（主参考）

> **来源：** 抖音 App → 我 → 创作者服务中心/数据中心；2024 年 9 月数据中心升级（作品表现、分体裁分析、进度条拖拽&弹幕分析等，据新榜等行业报道）；账号诊断/投稿分析类 API 公开口径补充。  
> **说明：** 入口名称以 App 实际展示为准；V1.0 演示使用 mock 数值。

| 指标 | 口径简述 | 创灵用途 |
|------|----------|----------|
| 播放量 | 作品被观看次数 | 曝光基线 |
| 平均播放时长 | 观众平均观看时长 | 诊断中段拖沓 |
| 完播率 | 完整播放次数 / 播放次数 | 内容质量核心 |
| 5 秒完播率 | 前 5 秒留存 | 验证钩子 AI（F2） |
| 2 秒跳出率 | 开头即划走占比 | 诊断开头吸引力（F2） |
| 点赞/评论/分享 | 单作品互动 | 计算互动率 |
| 涨粉量/粉丝净增量 | 净增粉丝 | 成长转化（F5） |
| 互动指数 | 观看+点赞+评论+转发综合 | 账号健康度 |
| 流量来源 | 推荐/搜索/关注/同城等 | 选题策略（F1） |
| 投稿数 | 周期发布作品数 | 创作效率供给侧（F3） |
| 分体裁指标 | 短视频/图文等差异指标 | 画像策略差异化 |
| 观看趋势/弹幕拖拽 | 掉点与互动热度 | V1.2 深度复盘 |

**业务理解：** 抖音推荐更重「留得住」而非「点得来」。高播放 + 低完播常见于标题党；AI 应优先优化 **5 秒完播与 2 秒跳出**，而非仅追播放量。

#### 6.2.2 小红书创作者中心（对标参考）

> **来源：** 创作者中心 → 笔记数据分析；行业对「曝光→点击→互动」漏斗的拆解。

| 指标 | 口径 | 对标意义 |
|------|------|----------|
| 曝光量 | Feed 展示次数 | 对应播放前的曝光环节 |
| 点击率 CTR | 点击 / 曝光 | 发布助手标题优化（F3） |
| 5 秒播放率 | 前 5 秒留存 | 与抖音 5 秒完播同构 |
| 互动率 | (赞+藏+评) / 阅读等 | 诊断「高曝低互」 |
| 完播率 | 完整看完占比 | 跨平台验证脚本 |
| 搜索词 TOP20 | 搜索来源词 + CTR | 选题搜索意图（V1.2） |

**业务理解：** 小红书常用「曝光×CTR×互动」漏斗；抖音更强调推荐流内完播。AI 选题需区分 **搜索型** vs **推荐型** 选题。

#### 6.2.3 快手创作者服务中心（对标参考）

> **来源：** 快手 App → 创作者中心 → 数据中心。

| 指标 | 口径 | 对标意义 |
|------|------|----------|
| 播放完成率 | 看完占比 | 等同完播率 |
| 跳出时间点 | 观众离开位置 | 对齐抖音进度条分析 |
| 互动转化率 | 互动 / 播放 | 内容行为强度 |
| 粉丝增长 | 周期涨粉 | 对齐抖音涨粉量 |
| 粉丝活跃时段 | 活跃时间分布 | 发布助手时段（F3） |
| 流量来源分布 | 渠道占比 | 发布与选题策略 |

**业务理解：** 快手更重关系与复访；抖音更重算法冷启动。同一脚本在快手需更强人设 CTA，在抖音需更强前 3 秒钩子。

#### 6.2.4 互动率统一口径（L1 计算用）

```
互动率 = (点赞 + 评论 + 分享) / 播放量 × 100%
```

#### 6.2.5 内容质量综合分（L1 → 支撑 P3）

```
内容质量分 = 
  normalize(5秒完播率) × 40%   ← 参考抖音分体裁/作品分析
+ normalize(完播率) × 35%        ← 参考抖音创作者中心
+ normalize(互动率) × 25%        ← 参考小红书互动拆解思路
```

### 6.3 L2：AI 产品运营指标（对齐 JD）

> **来源：** 岗位 JD（留存、创作效率、内容质量、成长转化、AI 建议质量、满意度）+ AI 助手类产品通用度量。

| 编号 | 指标 | JD 对齐 | 可操作定义 | L1 验证代理 | 目标（上线 4 周） |
|------|------|---------|------------|-------------|-------------------|
| **P1** | 创作者留存 | 留存 | D7 再次打开创灵占比 | — | ≥ 45% |
| **P2** | 创作效率 | 创作效率 | 选题→「发布准备完成」中位耗时 vs 基线 | 周期投稿数↑ | 耗时 **-30%** |
| **P3** | 内容质量 | 内容质量 | 采纳 AI 作品的质量综合分（见 6.2.5） | 5秒完播、完播、互动 | 综合分 **≥ 70** |
| **P4** | 成长转化 | 成长转化 | 完整采纳链路后 7 日粉丝净增 vs 同类基线 | 抖音涨粉量 | **+10%** |
| **P5** | AI 建议准确率 | 准确度 | 采纳且 7 日内 L1 正向占比 | 如 5 秒完播高于近 10 条均值 | **≥ 80%** |
| **P6** | 创作者满意度 | 满意度 | 链路结束 1 题五星 / NPS | — | **≥ 4.0/5** |

### 6.6 A/B 实验设计

| 实验 ID | 名称 | 变体 | 主指标（L1） | 护栏指标 | 参考平台 |
|---------|------|------|--------------|----------|----------|
| EXP-01 | 钩子模板 | 痛点型 vs 悬念型 | 5 秒完播率 | 2 秒跳出、完播率 | 抖音 |
| EXP-02 | 选题展示 | 卡片 vs 列表 | 选题采纳率 → 7 日播放 | 互动率 | 产品 |
| EXP-03 | 发布时段 | AI 推荐 vs 固定晚 8 点 | 发布后 1h 播放量 | 活跃时段匹配 | 快手 |
| EXP-04 | 合规预检 | 无 vs 有 | 违规/限流率↓ | 投稿数、发布成功率 | JD 合规 |
| EXP-05 | 标题优化 | AI 标题 vs 自拟 | CTR（若有） | 完播率（防标题党） | 小红书 |

**护栏原则：** 借鉴小红书「高曝低完播」诊断——CTR 提升不得伴随完播显著下降。

## 7. 验收标准

## 8. 技术方案（MVP · GitHub Pages + Mock）

| 项 | 选型 |
|----|------|
| 前端 | React 18 + Vite 6 + TypeScript + Tailwind |
| AI | 规则引擎（`app/src/services/aiEngine.ts`），**模拟** LLM 输出 |
| 数据 | `app/src/data/mockData.ts`；画像 `localStorage` |
| 图表 | Recharts |
| 构建 | `npm run build` → `app/dist` |
| 托管 | **GitHub Pages**（`.github/workflows/deploy-github-pages.yml`） |
| 路径 | CI 设置 `VITE_BASE_PATH=/douyin-creator-ai/` |
| 操作手册 | `docs/部署-GitHubPages.md` |

### 8.2 Mock 边界（答辩用）
