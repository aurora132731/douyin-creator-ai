# 创灵 · 未来迭代方向（V2.0 面试版 → 真实产品）

> 说明：本文描述**当前这一版实际做到了什么**、**哪些是 Mock**、**下一版要接什么 API / 大模型 / 平台能力**。与 `docs/PRD.md` §8、§9 一致，供面试「迭代（30s）」口述。

---

## 一、当前版本（V2.0 · 面试交付）实际状态

| 维度 | 现状 | 面试怎么说 |
|------|------|------------|
| **部署** | GitHub Pages 静态站 + Actions 自动构建 | 1 天可演示，无需服务器 |
| **后端** | 无 | 规则引擎在浏览器端 `aiEngine.ts` |
| **大模型** | 无真实调用 | 选题/脚本/诊断为**模板 + 词库**，验证链路与交互 |
| **抖音数据** | 无开放平台 | L1 四段漏斗、诊断雷达为 **Mock**，**结构对齐**创作者中心 |
| **用户体系** | 无登录 | 画像存 `localStorage`，演示阶段×垂类 |
| **埋点** | 无 | L2 指标（P1–P6）为静态 Mock + 趋势示意 |

**本版已验证（不必等 API 才能讲清楚的价值）：**

- 全链路 Tab 与 JD 对齐（选题→创作→发布→合规→成长→**AI 作品诊断**→指标）
- 抖音 **四段漏斗** 指标组织 + 小红书式 **现状/原因/建议** 诊断交互
- P3 质量分公式与权重原理、P5 诊断有效率定义
- 作品诊断：**先选作品 → 雷达基础数据 → 开始 AI 诊断 → 分维度弹窗**

## 二、分模块：Mock 什么 → 下一版接什么

### F1 AI 选题

| 项目 | 当前（V2.0） | 未来迭代 |
|------|--------------|----------|
| 选题生成 | `aiEngine.ts` 垂类词库 + 随机热度/竞争度 | **V1.1** 接入豆包/通义 **Chat API**，Prompt 含阶段×垂类 |
| 热点/趋势 | 静态 Mock 标题 | **V1.2** 抖音热点 API 或运营配置热榜 |
| 效果验证 | 无 | 埋点：采纳率、发布后 7 日播放环比 |

### F2 AI 创作（脚本）

| 项目 | 当前 | 未来迭代 |
|------|------|----------|
| 钩子/分镜/CTA | 模板拼接 | **V1.1** LLM 生成，约束 25–35 秒、黄金 3 秒结构 |
| 垂类风格 | 规则分支 | Prompt 注入垂类范例 + 用户历史高完播脚本 |
| 流式输出 | 无 | SSE 流式展示，降低等待焦虑 |

### F3 发布助手

| 项目 | 当前 | 未来迭代 |
|------|------|----------|
| 标题/标签/描述 | 模板生成 | **V1.1** LLM + 违禁词过滤 |
| 最佳时段 | Mock 文案 | **V1.2** 读创作者历史发布与播放曲线 |

### F4 合规预检

| 项目 | 当前 | 未来迭代 |
|------|------|----------|
| 检测方式 | 本地敏感词表 | **V1.1** 词库后台可配置；**V1.2** 接内容安全 API（若平台提供） |
| 违规样例 | 静态 Mock | 运营录入真实驳回 case 做 few-shot |

### F5+ AI 作品诊断（核心）

| 项目 | 当前 | 未来迭代 |
|------|------|----------|
| 作品列表/雷达 | `diagnosisMock.ts` 按垂类 Mock | **V1.2** 抖音开放平台 · 作品数据详情 API |
| 「开始 AI 诊断」 | 前端延时 2s + 预置解读文案 | **V1.1** LLM：输入漏斗指标 + 同类分位 → 输出现状/原因/建议 |
| 同类对标 | Mock 中位数 | **V1.2** 垂类×粉丝层级分桶统计（离线数仓或平台接口） |
| 重新诊断 | 前端可重复点击 | 对齐小红书：24h 后基于新数据重新生成 |

### F5 成长复盘 / F6 指标看板

| 项目 | 当前 | 未来迭代 |
|------|------|----------|
| L1 漏斗卡片 | Mock 数值 | **V1.2** 真实作品 ID 拉取 |
| L2 P1–P6 | 静态 + Recharts 趋势 Mock | 产品埋点：留存、采纳、满意度问卷 |
| A/B 实验 | 列表 Mock | 实验平台对接或内部配置后台 |

### 工程与架构

| 项目 | 当前 | 未来迭代 |
|------|------|----------|
| 前端 | React + Vite SPA | 保持；重型图表可拆包 |
| 后端 | 无 | **V1.1** 轻量 BFF（Node/Go）：鉴权、调 LLM、隐藏 Key |
| 配置 | 前端写死 | 运营后台：词库、Prompt、权重、垂类策略 |
| 部署 | GitHub Pages | 正式环境：字节内网 / 火山云 + CDN |

## 三、版本路线图（建议口述顺序）

### V2.0（当前 · 已完成）

- GitHub Pages 可演示
- 全链路 UI + 规则 Mock + AI 作品诊断交互闭环
- 双层指标定义（L1 抖音漏斗 + L2 JD 指标）

### V1.1 · 真 AI（约 2–4 周，需后端）

**目标：** 把「像 AI」变成「真生成」，诊断建议可随作品变化。

| 接入项 | 说明 |
|--------|------|
| 豆包 / 通义 Chat API | 选题、脚本、诊断三段式解读 |
| BFF 服务 | API Key 服务端保管；限流、日志、降级（失败回退模板） |
| Prompt 版本管理 | 按阶段×垂类多套 Prompt，可 A/B |

**仍可不接抖音数据：** 诊断输入仍可用 Mock 或用户手动录入关键指标做 POC。

### V1.2 · 真数据（约 1–2 月，依赖平台资质）

**目标：** L1 与诊断对标基于真实作品。

| 接入项 | 说明 |
|--------|------|
| 抖音开放平台 | OAuth 授权创作者；拉取作品列表、四段漏斗、流量来源 |
| 指标回流 | P3/P5 用真实 5 秒完播、完播、互动、CTR 计算 |
| 同类分位 | 离线任务或平台侧「超过 X% 同类」 |

### V2.x · 平台化（远期）

- 搜索词选题、进度条掉点、弹幕分析（PRD §6.2 辅助 Tab）
- 24h 诊断刷新、诊断采纳埋点驱动 P5
- 多创作者团队、MCN 看板

## 四、面试 30 秒迭代话术（可直接背）

> 当前 V2 是 **GitHub Pages + 前端 Mock**，把抖音漏斗口径和小红书式诊断交互做完整了，证明**链路 and 指标设计**成立。  
> 下一步 **V1.1** 加 BFF 接 **豆包/通义**，让选题、脚本、诊断变成真 LLM 生成；**V1.2** 再接 **抖音开放平台** 拉真实作品数据，让雷达和对标不是 Mock。  
> 这样是典型 AI 产品节奏：**先验证机制，再接入模型，最后接数据闭环**。

## 五、风险与前置条件

| 迭代 | 前置条件 | 风险 |
|------|----------|------|
| V1.1 LLM | API 账号、合规审核、成本预估 | 幻觉、延迟；需模板降级 |
| V1.2 数据 | 开放平台申请、用户授权 | 数据延迟 T+1；隐私与脱敏 |
| 正式上线 | 非「创灵」品牌、法务与免责声明 | 避免被误解为官方产品 |
