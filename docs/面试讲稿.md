## 一、3 分钟口播（连贯版，建议背这一段）

**【0:00–0:20 自我介绍 + 项目】**  
您好，我带来一个练习项目 **「创灵」**——面向抖音创作者的 AI 运营工作台，对应咱们岗位里的 **创作者全链路**：选题、创作、发布、合规和成长。  
在线可以点：https://aurora132731.github.io/douyin-creator-ai/ ，完整 PRD 在 GitHub 仓库里。

**【0:20–1:00 痛点 + 方案】**  
创作者常见四个问题：不知道拍什么、写得慢、怕踩合规红线、有数据但不知道下一步怎么改。  
抖音创作者中心已经有很多数据，但 **数据和行动之间缺一层 AI**。  
「创灵」就是把平台策略产品化：按 **创作者阶段 × 内容垂类** 给差异化建议——新手偏短脚本和低竞争选题，成长期偏系列化，头部更严合规。

**【1:00–2:30 演示（边说边点，见下一节）】**  
我快速走一遍主流程：改画像 → AI 选题 → 生成脚本 → 合规预检 → 指标看板。  
（按第二节操作，不要背细节，看着点就行。）

**【2:30–3:00 指标 + 收尾】**  
指标我拆了两层：**L1** 看内容有没有变好，比如 5 秒完播、完播率、涨粉，口径参考抖音创作者中心；**L2** 看工具值不值得迭代，比如留存、创作效率、AI 准确率，对齐 JD。  
当前是 **MVP**：GitHub Pages 可点 Demo + Mock 数据，先验证链路和指标设计；V1.1 接大模型，V1.2 接抖音开放平台。  
这是个人练习项目，不是官方产品。以上是我的介绍，谢谢。

## 二、演示操作脚本（边点边说）

按顺序点，**每步一句话**，不用全背。

| 步骤 | 点哪里 | 你说什么 |
|:----:|--------|----------|
| 1 | 总览 → **「开始演示」** | 这是工作台总览，覆盖 JD 要求的五段链路。 |
| 2 | 顶部改 **阶段 / 垂类** | 同一功能会随画像变，这是阶段乘垂类的个性化机制。 |
| 3 | 左侧 **AI 选题** → **采纳一条** | 根据垂类和阶段推荐选题，对应解决「选题难」。 |
| 4 | **AI 创作** → **生成脚本** | 输出钩子和分镜，目标是提升 5 秒完播，对应「创作慢」。 |
| 5 | **发布助手** | 有检查清单和标题标签草稿，对应发布前准备。 |
| 6 | **合规预检** → **「加载违规样例」** | 发布前扫敏感词和绝对化表述，对应 JD 里的内容安全。 |
| 7 | **成长复盘** | 给下期行动建议，形成选题到成长的闭环。 |
| 8 | **数据指标** | 这里是重点：L1 平台指标、L2 产品指标 P1 到 P6，还有 A/B 实验。 |
| 9 | **产品方案** | PRD 摘要，说明需求、指标和迭代路线。 |

**演示注意：** 合规那步一定要点「违规样例」，效果最明显。指标页停留 15 秒，体现数据思维。

## 三、指标（20 秒，指标页专用）

面试官问「你怎么衡量效果」，用这张表：

| 层级 | 回答什么 | 举例 |
|------|----------|------|
| **L1 内容结果** | AI 建议后，作品在平台上好不好 | 5 秒完播、完播率、涨粉（参考抖音创作者中心） |
| **L2 工具效果** | 这个 AI 产品要不要继续迭代 | 留存、创作效率 -30%、AI 准确率 ≥80%（对齐 JD） |

**一句话总结：** L1 验证内容价值，L2 验证产品价值，不能混用。

## 四、高频追问（各用一句话答）

| 问题 | 你怎么答 |
|------|------------|
| 为什么不用真 AI？ | MVP 先验证链路和指标口径；V1.1 接豆包或通义，风险更可控。 |
| 数据是真的吗？ | 数值是 Mock，但指标口径对齐抖音、小红书、快手和 JD。 |
| 和创作者中心有什么区别？ | 中心给数据；创灵在数据和行为之间加 AI 建议层。 |
| 怎么证明 AI 有效？ | 看 P5：采纳建议且 7 日内 L1 指标正向；用 A/B，比如钩子实验看 5 秒完播。 |
| 合规工具能上线吗？ | 定位是发布前辅助预检，不是法务终审，词库要运营更新。 |
| 为什么用 Mock 部署？ | 一天内交付可点击 Demo；机制验证完再接 API 和真实数据。 |
